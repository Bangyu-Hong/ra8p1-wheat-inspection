# 网页上位机现状与优化清单

## 1. 当前页面是否已经够用

当前页面已经能作为比赛联调主界面使用，不需要为了视觉效果再次整体重写。它已完成：

- 小麦计数、环境数据、设备状态分区显示。
- 小车四向微调和滑轨前后微调的 UI 预留。
- 田间行程、采样间隔、速度、超时、滑轨模式和停稳时间设置。
- 真实物理拍摄区域地图，而不是模型内部 12 个推理 tile。
- 向左 `X+`、向前 `Y+`、车体不转向的蛇形路线。
- 手机/电脑响应式布局、WebSocket 断线重连和控制租约显示。
- 能力门禁：底盘/滑轨未接入时不能误操作。

所以网页下一步应围绕“真实运动数据接入”和“比赛演示效率”优化，不应继续堆静态装饰。

## 2. 必须等底盘接入后完成的 P0 项目

| 优化 | 数据来源 | 完成标准 |
| --- | --- | --- |
| 小车真实位置同步 | M33 融合后的 `x/y/yaw` | 图标按真实坐标移动，不按时间猜测 |
| 目标与实际轨迹 | M85 任务目标 + M33 实际位姿 | 两条轨迹颜色分开，能看出偏差 |
| 运动/停稳状态 | M33 状态机 | 移动、减速、停稳、故障清楚显示 |
| 四轮状态 | 编码器和轮速 PID | 显示目标/实际轮速、PWM、异常轮 |
| IMU 状态 | JY61P 驱动 | 显示 yaw、角速度、数据年龄、漂移/掉线 |
| 当前物理区域 | 任务状态机 | 当前区域高亮，完成后写入一次计数 |
| 任务进度与 ETA | 已完成区域/总区域 | 展示百分比、已用时间、预计剩余 |
| 急停与安全状态 | 硬件急停/驱动故障/心跳 | 页面明显红色锁定，禁止继续任务 |

地图中的小车应使用连续的 `x_mm/y_mm` 映射，不再只依赖离散的 `field_row/field_column`。
离散字段继续用于区域计数索引，二者不能混为一个数据。

## 3. 比赛展示建议的 P1 项目

- 增加“演示模式”：只保留摄像头、计数、环境、地图和大号开始/暂停/停止，隐藏诊断细节。
- 增加“调试模式”：展开轮速、PID、IMU、IPC、队列、SD 和网络诊断。
- 在地图旁显示总计数、当前区域计数、已完成/失败/待拍数量。
- 增加任务参数“修改未下发 / 已校验 / 已应用”的明确状态，避免误以为输入框变化已生效。
- 开始任务前生成摘要：过道数、拍摄区域总数、预计路线长度、预计耗时和存储量。
- 手动微调使用按下开始、松开停止或明确的单次距离语义；手机端防止长按触发浏览器菜单。
- 对危险命令使用短确认：开始整田任务、清零累计、复位故障，不对普通页面操作反复弹窗。
- 增加当前 IP、固件版本、模型版本和任务 ID 的一键复制，方便现场排障。

## 4. 可以后置的 P2 项目

- 地图缩放、拖动、历史任务回放。
- 从 SD 读取区域日志并恢复地图。
- 现场标定向导：输入相机安装高度，辅助测量单张照片地面视野。
- 导出 CSV/JSON、打印巡检报告。
- 本地/云端大模型对话框，将自然语言转换为候选任务计划。
- JPEG 单帧快照浏览。连续视频通过 ESP8266 不是当前优先项。

## 5. 不建议做的改动

- 不在浏览器里模拟已经到位的小车位置。
- 不让网页成为任务状态权威；刷新页面不能导致任务丢失或重新开始。
- 不把 HMI 控件名、页面号或厂家串口命令写进业务层。
- 不以每 250 ms 遥测刷新次数累计小麦数量。
- 不在 ESP8266 上发送连续 RGB565 视频；带宽和内存不划算。
- 不为了“看起来工业级”引入复杂账号系统。当前比赛 LAN 原型保持一个控制端、其他观察端即可。

## 6. 页面源码位置

- 页面主体：`workspace/camera/src/web_ui_page.inc`
- 页面资产和 CRC：`workspace/camera/src/web_ui_asset.c`
- WebSocket/HTTP：`websocket_protocol.*`、`http_protocol.*`
- 多连接与控制租约：`lan_session_router.*`
- 遥测 JSON：`local_tcp_session.c`
- 任务参数：`mission_plan.*`

网页字段新增顺序应是：先在运动/任务模块产生真值，再加入 `app_telemetry_snapshot_t`，然后扩展
JSON 和网页。禁止先画一个 UI 字段，再从页面内部虚构数值。
