# 底盘、JY61P、编码器与 PID 开发交接方案

## 1. 交付目标

让四轮麦轮小车在整个田间巡检过程中保持车头朝向不变，准确执行前进、后退、左移、右移和
指定 X/Y 位姿移动，停车后能可靠判断“已经到位且机械停稳”，再允许 M85 拍摄和推理。

控制目标不是让每个电机“差不多转”，而是建立如下闭环：

```text
目标区域/手动微调
      -> 目标位姿 x*, y*, yaw*=0
      -> 外环位姿控制器
      -> 目标车体速度 vx*, vy*, wz*
      -> 麦轮逆运动学
      -> 四个目标轮速
      -> 四路轮速 PID
      -> PWM + 方向

四编码器 -> 实际轮速 -> 麦轮正运动学 -> 编码器里程计 --+
JY61P I2C -> yaw/gyro ------------------------------------+-> 融合位姿 x,y,yaw
```

## 2. 为什么编码器和 JY61P 要一起用

四个编码器擅长测量每个轮子转了多少，可以得到轮速和移动距离，但麦轮在土地上容易打滑，
左右轮误差还会导致车体慢慢转偏。JY61P 可以较快测到车身的偏航角和角速度，适合纠正“车头
是否偏转”。

JY61P 是六轴模块，没有磁力计或外部绝对定位。厂商明确说明动态和振动环境下航向角存在积分
累计误差，所以它不能单独告诉系统小车在田里哪个 X/Y 位置，也不能保证长时间绝对北向。

本方案采用：

- X/Y 位移：编码器里程计为主。
- 短时航向和角速度：JY61P 为主。
- 编码器计算的旋转增量：用于连续性、异常检测和 IMU 漂移约束。
- 加速度：用于检测碰撞/强振动或静止辅助，不做二次积分求位置。

## 3. JY61P 接口与接线规划

JY61P 支持串口和 I2C。当前串口全部有明确用途，因此选 IIC1：

| JY61P | RA8P1 | 扩展板 | 说明 |
| --- | --- | --- | --- |
| SDA | P511 / SDA1 | P6-38 | IIC1 数据 |
| SCL | P512 / SCL1 | P6-40 | IIC1 时钟 |
| GND | GND | P10 可靠 GND | 必须与主控、电机驱动共地 |
| VCC | 按实物规格确认 | 稳定电源 | 不凭网图猜 3.3 V/5 V；先看手中 12Pin 丝印和规格 |

7-bit 地址按 `0x50` 规划。P511/P512 已由 CPKHMI 引脚复用表和 Titan IIC1 示例确认，不与
OV5640 的 IIC0 P409/P410 冲突。

注意：I2C 是开漏总线，需要上拉。先确认 JY61P 模块板和 RA8P1 板是否已有合适上拉；不能因为
GPIO 可以内部上拉就默认长线和电机干扰下仍可靠。正式接线时使用短线、远离电机线，必要时在
模块侧加入外部上拉和地线伴随。首版硬件 I2C 建议 100 kHz，稳定后再评估 400 kHz。

## 4. JY61P 软件设计

- 使用 FSP `r_iic_master`，不要把参考教程的软件模拟 I2C 直接移植到 100 Hz 控制环。
- 事务异步推进：发起寄存器读 -> 回调置完成事件 -> 下一控制周期消费最新完整样本。
- 一次连续读取所需寄存器，避免每个角度分别发起事务。
- 每份样本带 `sequence`、时间戳、有效位和错误计数。
- 控制环只读取最近的完整快照；不得在控制中断中等待 I2C。
- 启动静止时完成水平/零偏检查和软件 yaw 归零。不要每次启动都把配置反复写入模块 Flash。
- 角度差使用环绕函数归一化到 `[-180°, 180°)`，否则从 179° 到 -179° 会被误算成 358°误差。
- 超过规定数据年龄（建议先从 50 ms 验证）标记 IMU stale；不能继续使用旧角度假装实时。

建议读出：Roll、Pitch、Yaw、Z 轴角速度、三轴加速度。运动闭环最关键的是 Yaw 和 Gyro Z。

## 5. 四编码器与轮速计算

已预留四组 GPT AB 相计数：

| 轮子建议命名 | GPT | 引脚 |
| --- | --- | --- |
| FL 左前 | GPT5 | P915/P914 |
| FR 右前 | GPT10 | P810/P811 |
| RL 左后 | GPT12 | P909/P908 |
| RR 右后 | GPT13 | P515/P514 |

最终轮序必须用架空单轮测试确认，不可只按线色命名。每个控制周期读取计数差：

```text
delta_count = current_count - previous_count（考虑 32-bit 回绕）
wheel_rev_s = delta_count / counts_per_wheel_rev / dt
wheel_mm_s  = wheel_rev_s * pi * measured_wheel_diameter_mm
```

`counts_per_wheel_rev` 必须包含编码器 PPR/CPR 定义、AB 四倍频和减速比。商家写的“线数”不一定
等于最终每轮计数，必须转一整圈实测。四个轮子的正方向单独配置，不要靠交换公式隐藏接线错误。

## 6. 麦轮运动学

设车体坐标 `vx` 向前、`vy` 向左、`wz` 逆时针，轮半径为 `r`，半轮距与半轴距之和为
`k = L + W`。常见 X 型麦轮的一个公式是：

```text
wFL = ( vx - vy - k*wz) / r
wFR = ( vx + vy + k*wz) / r
wRL = ( vx + vy - k*wz) / r
wRR = ( vx - vy + k*wz) / r
```

但轮子安装方向、驱动器正方向和编码器正方向会改变符号。实现时先把公式写成可配置矩阵，再做
四项实测：纯前进、纯左移、纯旋转、单轮正转。未通过这四项前不要调 PID。

正运动学把四轮实际速度还原成车体 `vx/vy/wz`，再用融合 yaw 将车体速度旋转到现场 X/Y 坐标
进行积分。

## 7. 姿态融合方案

首版采用互补融合，不直接上 EKF：

1. 编码器正运动学得到 `wz_encoder` 和位移增量。
2. JY61P 给出 `yaw_imu` 与 `gyro_z`。
3. 预测航向：`yaw_pred = yaw_prev + gyro_z * dt`。
4. 用较小比例把预测值拉向可信的 `yaw_imu`，并用编码器旋转增量做一致性检查。
5. IMU 过期/异常时短时退化为编码器 yaw；编码器明显打滑时降低其旋转权重。
6. 只有同时可信的航向用于把车体 `vx/vy` 转换成田间 `X/Y`。

不要在文档阶段写死融合系数。记录原始编码器 yaw、IMU yaw、融合 yaw 和控制误差，实测直行、
横移和蛇形换道后再选择系数。如果互补融合在真实土地上仍不能满足区域误差，才升级 EKF；EKF
不会凭空消除轮胎打滑和六轴 yaw 漂移，仍需要正确标定和外部参考点。

## 8. 级联 PID 控制

### 8.1 内环：四个轮速 PID（100 Hz）

输入为每个目标轮速与实际轮速之差，输出为 PWM。建议先用 PI，再按需要加入经滤波的 D：

- 启用 PWM 饱和和最小有效占空补偿。
- 积分抗饱和：输出已饱和且误差继续同方向增长时停止积分。
- 目标速度使用斜坡限制，避免瞬间冲击和车体打滑。
- 目标为零时进入受控刹车/停止逻辑，停稳后清理积分。
- 四个电机参数分别保存，但首轮尽量从相同参数开始，避免用参数掩盖机械问题。

### 8.2 外环：X/Y/航向控制（20-50 Hz）

外环输入为目标位姿与融合位姿误差，输出 `vx*/vy*/wz*`：

- 正常巡检 `yaw*=0`，航向 PID 持续抵消车体旋转。
- 沿 Y 行驶时，X 外环修正横向偏移；沿 X 换道时，Y 外环修正纵向偏移。
- 临近目标采用减速曲线，避免高速冲过目标后反复摆动。
- X/Y 速度、角速度、加速度和加加速度均设上限。
- 误差进入小窗口且轮速/角速度连续稳定若干周期后，才声明 `settled`。

### 8.3 调参顺序

1. 架空确认方向、编码器、急停和驱动使能。
2. 单轮开环 PWM -> 转速曲线，确定死区和方向。
3. 单轮 P，再加 I；四轮分别通过阶跃测试。
4. 四轮纯前进/横移，不开位姿外环，验证运动学。
5. 只开航向外环，调到直行/横移不明显转头。
6. 再开 X/Y 位置外环，先低速 100-300 mm 位移。
7. 最后调蛇形换道、停稳和带摄像头/滑轨实际负载。

一次只调整一层。轮速内环不稳定时，禁止调位姿外环。

## 9. M33 运动状态机

建议状态：

```text
BOOT -> SAFE_DISABLED -> CALIBRATING -> READY
READY -> MOVING -> DECELERATING -> SETTLING -> ARRIVED
任意运行态 -> STOPPING -> READY
任意状态 -> FAULT_LATCHED / ESTOP_LATCHED
```

M33 必须在 M85 心跳丢失、调试暂停、急停、驱动故障、编码器异常、IMU严重过期或控制周期超时
时关闭全局使能和 PWM。急停还必须硬件直接切断驱动使能，不能只依赖软件读取 P008。

## 10. M85/M33 IPC 最小契约

命令至少包含：协议版本、序号、目标模式、目标 X/Y/Yaw、速度/加速度上限、超时、停止/急停复位。

状态至少包含：协议版本、序号、时间戳、M33 状态、X/Y/Yaw、目标位姿、四轮目标/实际速度、
四路 PWM、IMU/编码器有效性、到位/停稳、急停/驱动故障和控制周期最大值。

IPC 使用固定大小结构、版本、长度和 CRC/校验，启动时双方完成版本和 ready 握手。序号相同的
重复命令不得重复执行位移。

## 11. 需要新增到网页的运动遥测

- `pose_x_mm`、`pose_y_mm`、`yaw_mdeg`。
- `target_x_mm`、`target_y_mm`、`target_yaw_mdeg`。
- `velocity_x_mm_s`、`velocity_y_mm_s`、`yaw_rate_mdeg_s`。
- 四个目标/实际轮速和 PWM。
- `motion_state`、`settled`、`imu_valid`、`encoder_valid_mask`。
- 控制周期 P99/max、IMU 数据年龄、姿态误差和运动故障码。

网页小车图标使用连续位姿；`field_row/field_column/slide_position_index` 只作为拍摄区域索引。

## 12. 开发阶段和验收门槛

### 阶段 A：双核与安全

- 两核分别构建、下载并握手。
- 未收到有效命令时 PWM 始终为 0。
- 断开 M85 心跳、按急停或暂停调试后，驱动在规定时间内关闭。

### 阶段 B：编码器与轮速

- 四个编码器方向正确，转一圈计数可重复。
- 四轮 100 Hz PID 无持续振荡，P99 控制周期满足预算。
- 堵转/断编码器被检测并停止。

### 阶段 C：JY61P 与融合

- I2C 读取稳定，错误和数据年龄可观测。
- 静止、前进、横移、原地旋转方向均正确。
- 强振动/拔线时进入明确降级或故障，不输出跳变航向。

### 阶段 D：位姿与任务

- 100/300/1000 mm 前进和横移重复误差达标。
- 蛇形路线车身朝向不变，换道包含 350 mm 过道和扫描覆盖宽度。
- 到位后连续满足位置、角度和速度窗口，才允许拍照。
- 网页图标、目标轨迹和实际轨迹与实车同步。
