## 3. 接管顺序

1. 先读本文件、`02_当前进度与验收状态.md` 和自己的专项交接文档。
2. 不要从根目录随便选一个工程；唯一产品主工程是 `workspace/camera`。
3. 底盘开发先建立 RA8P1 双核 Solution 和 CPU1/M33 独立工程，保留当前 M85 工程可回退。
4. 串口屏使用已预留 SCI3，不直接修改视觉、网络、存储或运动状态。
5. 两个队友都通过统一状态快照和命令接口集成，不各自创建第二套任务参数。
6. 合并前先做各自模块测试，再做摄像头、LCD、AI、网络、SD 的完整回归。

## 4. 当前最重要的约束

- 小车采用麦轮，车身朝向在巡检过程中保持不变，只前后移动和左右横移。
- 现场坐标为向左 `X+`、向前 `Y+`；摄像头和 300 mm 滑轨位于小车右侧 `X-`。
- 运动控制必须使用四编码器闭环；JY61P 只负责航向/角速度修正，不能代替编码器测位置。
- 串口已经分配：SCI0 ESP8266、SCI3 串口屏、SCI8 ZDT42、SCI9 调试；JY61P 使用 IIC1。
- 当前模型可以执行板端推理，但小麦检测准确率仍需继续优化，不得把“能跑”写成“精度验收完成”。
- 当前工作树包含大量尚未提交的新代码；本交付包的源码快照是 2026-08-18 的确定恢复点。
- `esp_at_credentials.h` 含本地 Wi-Fi 凭据，不进入交付包、Git 或普通日志。
