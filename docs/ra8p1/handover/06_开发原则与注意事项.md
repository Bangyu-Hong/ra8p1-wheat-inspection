# 开发原则与注意事项

## 1. 项目目标与比赛取舍

- 目标是可靠、流畅、可展示的比赛系统，不追求无必要的工业级复杂度。
- 不机械追求最小改动；公共接口、状态所有权、错误恢复、性能测量和双核迁移要为后续留路。
- 也不一次堆入所有未来功能。每阶段只引入一个主要硬件或算法不确定量，完成验收再继续。
- 功能展示优先级：安全运动 > 稳定拍摄/计数 > 区域记录 > 网页/串口屏一致 > 云端扩展。

## 2. 唯一主工程和 Git 范围

- 唯一产品工程是 `workspace/camera`。`RA8P1/`、`STM32/`、`kuozhanmokuai/` 和厂商例程都是参考。
- Git 根目录是 `F:\Desktop\RenesasCup`，但可以只提交 camera 相关路径，例如：

```powershell
git add -- workspace/camera
git commit -m "feat(camera): ..."
```

- 不要使用不限定路径的 `git add .`，否则可能把数据集、模型输出、凭据和大型资料混入提交。
- 当前工作树有大量未提交改动。接管者先保存状态、查看差异，不得用 `git reset --hard` 或
  `git checkout --` 覆盖现有工作。

## 3. FSP 与生成代码

- 当前 FSP 是 6.5.0，器件是 `R7KA8P1KFLCAC`。
- 改外设、引脚、中断或时钟时只修改 `configuration.xml`，再执行 Generate Project Content。
- 不手改 `ra/`、`ra_gen/`、`ra_cfg/`、`Debug/`、`Release/` 中的生成内容。
- 每次 Generate 后必须检查 CEU `bytes_per_pixel=1`、SDHI、OSPI、UART 和引脚表没有意外漂移。
- FSP 6.5.1 可以评估，但不要在底盘/双核首轮同时升级 FSP；否则无法判断问题来自版本还是功能。

## 4. 引脚与电气

- 选择顺序：开发板原理图与实际引出 -> RA8P1 复用表 -> FSP Pins -> `configuration.xml` -> 生成代码。
- 芯片支持某复用不代表开发板已引出；扩展板实体针脚不能按 MCU 端口号顺序猜。
- 所有模块共地，先核对电源电压、逻辑电平和峰值电流，再接信号。
- 电机、步进驱动和 ESP8266 产生较强干扰；编码器、I2C、摄像头和限位线应短、清晰标记并远离
  电机电源线。I2C 必须确认上拉，不默认仅靠内部弱上拉。
- 插拔摄像头、LCD、IMU、驱动器或修改电源接线前先断电。

## 5. 调度与实时性

- 当前 M85 使用协作式状态机。每个 `process/poll` 每次只做有界工作，不能无限等待。
- ISR/回调只记录事件、时间戳或少量字节，不做 JSON、文件写入、AT 事务、图像处理或 PID 调参。
- AI、摄像头和 LCD 优先于 SD、网络和普通日志；运动安全控制必须放到 M33 独立 100 Hz 周期。
- 所有等待都有超时、错误码、有限重试和降级/停止路径。
- 网页、SD、HMI、网络都使用有界队列或“只保留最新值”，不能无限累积。

## 6. DMA、Cache 与内存

- CEU 已直接写 SDRAM，不再额外叠加 DMAC。
- SDHI 使用当前 FSP 支持的 DMAC0；UART/I2C 只有测出 CPU/抖动瓶颈后才增加 DMA/DTC。
- DMA、CEU、NPU、另一核心共享缓冲时必须明确唯一写所有者和 D-Cache clean/invalidate 边界。
- 大帧、大模型、大 arena 放 SDRAM/OSPI；控制状态、队列和栈放内部 SRAM。
- 不用“BSS 总数”直接判断内部 SRAM 溢出，必须查看链接 map 中每个段的地址。
- 主栈和任务栈不能无限增大。依据 map、调用深度、高水位和中断嵌套测量配置。

## 7. 状态和协议所有权

- RA8P1 内部状态是系统真值。网页、串口屏、CSV 和云端只是投影或请求源。
- 所有外部请求经过版本、长度、类型、范围、能力、当前状态和重复序号校验。
- 同一命令重复到达不能重复执行距离移动、计数累加或配置写入。
- 网页和串口屏使用同一 `MissionPlanV1`，不各自创建独立的“最终参数”。
- 网络恢复/HMI 重连后先发送完整状态快照，再发送增量。

## 8. 运动安全

- 急停必须硬件切断全局驱动使能，同时提供软件状态输入；不能只依赖主循环。
- 调试暂停、M85/M33 心跳丢失、控制周期超时、编码器故障或驱动故障时，M33 必须清 PWM 并关使能。
- 首次电机测试必须架空轮子、限制 PWM、准备物理断电，不直接放在地面高速试车。
- 运动控制先轮速内环、再运动学、再航向、最后 X/Y 位姿；不能同时乱调所有 PID。
- 小车到位必须同时满足位置、角度和速度窗口若干周期，不能只看延时。

## 9. AI 与计数

- 模型“转换成功/能运行”和“检测精度通过”是两回事。每个模型记录版本、hash、量化、算子分配、
  PC 精度、板端输出和延迟。
- 当前使用 640×480 完整帧生成多个 tile224，分块检测后做全局 NMS。
- 地图方格是一张完整照片区域，不是 tile；区域计数只在一次成功推理事务完成后累加一次。
- 相邻拍摄区域重叠会重复计数，采样间隔必须按真实安装高度和视野标定。
- 替换模型时不只替换一个文件，要同步 manifest/hash、输入量化、输出布局和后处理参数并回归。

## 10. 存储、网络和凭据

- SD 的 `FIELD.BIN` 是带版本/长度/CRC 的权威追加日志，CSV 是人读投影。
- 拔卡、满卡、断网或 HMI 断开不阻塞视觉和运动安全。
- Wi-Fi 密码只放被忽略的 `esp_at_credentials.h` 或未来 A/B 配置，不写进 Git、普通日志和交付包。
- 当前网页无登录，只适用于可信局域网。任何同网设备可能在租约空闲时成为控制端。
- 云端密钥只放电脑/可信网关；ESP8266、RA8P1、SD 和串口屏不保存云端 API key。

## 11. 构建、测试和用户协作

- 大改动必须至少完成相关主机测试和 Release/Debug 构建；小文档或低风险局部修改可判断跳过构建。
- FSP/引脚/中断、Cache/DMA、双核、模型和运动控制属于大改，必须构建并实板验收。
- 命令行优先。只有 FSP Generate、必要调试器功能无法可靠命令行完成时才请用户操作界面。
- 需要用户接线、插拔、按键或 Generate 时，立即停止长时间尝试，清楚说明一次需要做什么。
- 不反复卡在 GUI；记录命令、镜像 hash、板上输出和结论。

## 12. 每阶段验收模板

每个阶段至少覆盖：正常、边界、故障、恢复、压力。

记录：

- 工程/分支/工作树标识、FSP、编译器和配置。
- 固件/模型/配置 hash。
- 输入、步骤、预期、实际结果和原始日志位置。
- P50/P95/P99/max 耗时、控制周期、队列高水位和错误计数。
- 断电/复位/拔线后的恢复方式。
- 明确失败项和回退镜像，不用“基本正常”代替结论。
