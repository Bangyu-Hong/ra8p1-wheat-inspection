# 项目总体方案与系统架构

## 1. 项目目标

在研究院试验田中，麦轮小车沿田间过道运动，右侧架高支架上的 OV5640 垂直俯视小麦区域。
小车按固定距离停车，滑轨移动到规划位置，等待机械停稳后冻结一帧完整图像，使用 RA8P1 的
Ethos-U55 NPU 执行小麦检测和计数，同时采集温湿度与光照。每个物理拍摄区域的数量和环境
数据写入 SD 卡，并通过 ESP8266 提供给同一局域网内的手机、电脑和平板浏览器。

最终展示内容包括：

- 实时摄像头画面与单帧检测框。
- 当前照片计数、本次任务累计和整片试验田累计。
- DHT11 温湿度、模拟光敏值和设备健康状态。
- 试验田拍摄分区地图、蛇形路线、小车/滑轨实际位置和区域计数。
- 网页上位机与串口屏的任务设置、手动微调、开始/暂停/停止和故障显示。
- SD 本地记录、局域网访问，以及后续可选的云端大模型任务规划。

## 2. 已确定的机械与坐标约定

- 小车为四轮麦克纳姆轮底盘，车体不在行尾掉头。
- 向左为现场坐标 `X+`，向前为 `Y+`，逆时针偏航定义为正。
- 正常巡检路线为 `Y+ -> X- 换道 -> Y- -> X- 换道` 的蛇形路线。
- 摄像头和滑轨安装在小车右侧，即 `X-` 方向。
- 滑轨最大机械行程 300 mm。
- 默认小车过道宽度 350 mm，最终值必须以真实试验田测量为准。
- 一个网页地图方格代表一张完整照片覆盖的物理区域，不是 YOLOX 内部 tile。

## 3. 硬件组成

| 子系统 | 当前/规划硬件 | 主要接口 |
| --- | --- | --- |
| 主控 | RA8P1 CPKHMI 板 | Cortex-M85 + Cortex-M33 + Ethos-U55 |
| 摄像头 | 正点原子 OV5640 DVP | IIC0/SCCB + CEU 8-bit |
| 本地视频屏 | ST7796S IPS + 40001 转接板 | 16-bit I8080 GPIO 分组写 |
| AI | YOLOX-Tiny tile224 INT8 | OSPI 模型 + Ethos-U55 + M85 后处理 |
| 环境 | DHT11 + 模拟光敏 | P010 单总线 + P513/AN016 ADC |
| 联网 | ESP-01/ESP-01S | SCI0 AT，HTTP/WebSocket 服务 |
| 存储 | 板载 microSD | SDHI0 4-bit + FatFs + DMAC0 |
| 串口屏 | 队友提供 HMI 工程 | SCI3 P905/P310 |
| 滑轨 | ZDT42 步进电机 | SCI8 P805/P806 + 双限位 |
| 底盘 | 四电机、四 AB 编码器、驱动器 | 4 PWM + 4 GPT 编码器 + 8 方向 GPIO |
| 姿态 | JY61P 六轴 IMU | IIC1 P511/P512，地址规划为 0x50 |

## 4. 当前单核数据流

```text
OV5640 -> CEU -> SDRAM RGB565 帧
                   |-> ST7796S 实时显示
                   |-> USER/网页触发冻结
                   |-> tile224 预处理 -> Ethos-U55 -> YOLOX 后处理/NMS
                                              |-> 检测框与数量

DHT11/光敏 -> 环境服务 -> 统一遥测快照
AI结果 -----------^          |-> LCD/未来串口屏
设备状态 ----------^          |-> SD FIELD.BIN/FIELD.CSV
                              |-> ESP8266 -> HTTP/WebSocket -> 浏览器
```

所有界面只是状态投影，`app_telemetry_snapshot_t` 和后续运动控制状态才是板端真值。网络、
SD、HMI 变慢或断开时，不允许反向阻塞摄像头、AI 或未来电机安全控制。

## 5. 推荐双核最终架构

现在接入底盘就是切换双核方案的合适阶段。原因不是单纯追求更高算力，而是当前 AI 单帧推理
和图像处理会占用较长时间，四轮控制的 100 Hz 周期不能因此停顿。

```text
CPU0 / Cortex-M85（现有工程演进）
  摄像头、CEU、SDRAM帧、LCD、Ethos-U55、AI后处理
  DHT11、光敏、SD、ESP8266、HTTP/WebSocket、串口屏
  田间任务编排：决定下一目标点、何时拍摄/推理/记录
                         |
             固定大小 IPC 命令/状态 + 心跳
                         |
CPU1 / Cortex-M33（底盘队友新建）
  四路PWM、四路AB编码器、方向/使能/急停/驱动故障
  IIC1 JY61P、麦轮运动学、里程计、姿态融合
  100 Hz轮速PID、20-50 Hz位姿控制、停稳判断
  SCI8 ZDT42与两端限位、运动安全监督
```

两个核心不得同时初始化同一外设或引脚。M85 只发送目标位姿、滑轨目标和停止命令；M33 返回
实际位姿、轮速、到位/停稳、IMU/编码器健康和故障。IPC 不传整帧图像。

## 6. 田间任务状态机

```text
空闲
 -> 校验任务参数与硬件能力
 -> 底盘移动到拍摄点
 -> 编码器/IMU确认到位
 -> 底盘停稳
 -> 滑轨移动到目标位置
 -> 限位/位置确认并停稳
 -> 冻结完整摄像头帧
 -> 分块推理与全局NMS
 -> 记录当前区域计数和环境
 -> SD入队 + 网络最新值更新
 -> 下一个滑轨位置 / 下一个Y点 / 换道
 -> 任务完成
```

任何步骤必须有超时和可诊断结果。推理完成并形成记录之前，滑轨和小车不得前往下一位置。

## 7. 存储与内存用途

| 存储区域 | 容量/性质 | 项目用途 |
| --- | --- | --- |
| 内部 Code MRAM | 1 MiB，掉电保存 | 启动代码、主要程序；TrustZone Secure 边界已修复为 1 MiB |
| 内部 SRAM | 约 2 MiB，速度快、掉电丢失 | 栈、小控制结构、队列、热数据 |
| 外部 SDRAM | 16 MiB，掉电丢失 | 摄像头帧、冻结帧、NPU arena 和大缓冲 |
| 板载 OSPI NOR | 32 MiB，掉电保存 | AI 模型/command stream、网页只读资产 |
| microSD | 可更换、掉电保存 | 田间长期日志、导出数据和未来快照 |

程序运行时普通局部变量主要在栈，静态/全局变量在 SRAM 或链接脚本指定的 SDRAM 段；模型和
网页资产从 OSPI 读取。禁止把大帧、大数组或网络大缓冲放进小栈。

## 8. 联网和上位机方案

ESP8266 只作为 AT 控制的 Wi-Fi/TCP 调制解调器，HTTP 路由、WebSocket、遥测、命令校验和
任务状态由 RA8P1 持有。同一 Wi-Fi 内任何设备打开 `http://<板卡IP>/` 即可访问。

当前不接云平台。以后接入云端或本地大模型时，大模型只把自然语言转换成候选
`MissionPlanV1`，必须经过范围、能力、状态和用户确认，不能直接生成 PWM/GPIO 命令。

## 9. 长期演进顺序

1. 建立 M33 底盘最小安全工程和双核 IPC 握手。
2. 完成单轮、四轮轮速闭环和编码器标定。
3. 接入 JY61P I2C，完成航向保持和融合里程计。
4. 完成 X/Y/航向位姿控制、停稳判定和网页真实位置同步。
5. 接入 ZDT42、限位与拍摄区域状态机。
6. 串口屏接入统一状态和任务协议。
7. 完成整田蛇形巡检、区域日志和掉电恢复。
8. 用更优模型替换当前 YOLOX 资产并回归精度/性能。
9. 只有实测需要时再加入 EKF、更复杂路径规划、云端大模型或连续图像上传。
