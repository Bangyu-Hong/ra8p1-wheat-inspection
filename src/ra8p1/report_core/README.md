## 目录结构

- `include/`：公共接口、系统配置和共享数据类型。
- `src/`：摄像头、传感器、模型推理、通信、存储和状态机等核心程序。
- `board_port.h`：FSP 外设实例、开发板引脚和文件系统的适配接口。
- `wheat_model_port.h`：RUHMI 模型初始化与推理调用的适配接口。
- `附录A_核心代码说明.md`：可用于设计报告附录的程序说明、故障路径和验证记录表。

## 硬件适配边界

与开发板相关的操作统一通过 `board_port.h` 接入，包括摄像头数据通道、GPT 或 DWT 微秒计时源、ADC 单元与通道、HMI 和 ESP8266 串口实例、SDHI/FileX 文件系统以及 RTC 时间。

最终工程必须使用 FSP 配置器实际生成的外设实例、引脚名称、中断优先级和 DMA/DTC 通道。OV5640 的 SCCB 地址使用 7 位地址表示，摄像头时钟、DVP 数据极性、行场同步和帧缓冲区地址应与当前硬件连接一致。

## 模型文件说明

模型权重数组及 RUHMI 自动生成文件不放入报告正文。项目通过 `wheat_model_port_init()` 和 `wheat_model_port_invoke()` 接入生成模型，最终提交时应记录以下信息：

- 原始模型文件名称和校验值；
- INT8 量化方式及校准数据集；
- RUHMI 转换版本和生成日期；
- 输入输出张量的形状、数据类型、scale 和 zero point；
- 通道顺序、候选框格式和置信度阈值；
- 模型中可映射至 Ethos-U55 的算子情况。

`wheat_ai.c` 当前按照 RGB 通道顺序，将 0～255 像素值转换为 -128～127 的 INT8 输入。该处理必须与最终模型的张量元数据完全一致。

## 主要运行流程

系统收到串口屏的开始命令后，依次执行环境数据采集、光照检查、OV5640 单帧采集、图像质量判断、重叠分块推理、坐标回映射、全局 NMS 去重、结果保存和网络上传。

DHT11 校验失败时只将温湿度标记为无效，不使用错误数据，也不中断核心图像检测。TF 卡不可用时继续本地显示和网络上传；ESP8266 断开或 ACK 超时时，将检测记录写入待上传缓存。摄像头超时、图像质量不合格或模型调用失败时，不输出本次计数结果。

## 提交前验证清单

每项结果应填写为“未测试”“通过”或“失败”，并保留对应日志、照片或测试记录编号。

1. 核对 OV5640 芯片 ID、寄存器回读结果和连续 100 帧采集情况。
2. 使用正常数据和故意破坏校验位的数据验证 DHT11 校验路径。
3. 完成光敏电阻暗端、亮端标定，并检查滤波后读数的重复性。
4. 使用过暗、过亮、模糊和正常图像核对质量判断阈值。
5. 核对 RUHMI 输入输出张量、量化参数和单分块推理结果。
6. 使用跨越分块边界的麦穗验证坐标回映射和全局 NMS。
7. 测试 ESP8266 正常 ACK、错误 CRC、网络断开和重连路径。
8. 测试 TF 卡未插入、写满和检测过程中移除时的降级路径。
9. 记录实际推理时间、内存占用、识别结果和网络上传成功率。

未经实际测试的数据应保留为“待实测”，不得使用估算结果替代实测结论。
